# 도하 · 승원에게 — 대시보드 연동 & 데이터 기반 제안 (유진)

대시보드(Next.js + Supabase)가 카드와 성과를 함께 보여주고, 팀의 선택/패스/재생성/게시 URL을 `card_events`에 쌓습니다.
이 데이터로 점수 로직과 카드 생성을 어떻게 고치면 좋을지 화면(`/insights`)에서 자동으로 제안이 나오도록 해 두었어요.
아래는 처음부터 반영해 주시면 좋은 것들입니다.

## 1. 공통 — 데이터 계약

- 카드 JSON 스키마는 `lib/types.ts`의 `Card` 기준입니다. 필드를 바꾸면 `cards` 테이블과 같이 맞춰야 해요.
- `card_id` = `YYYY-MM-DD-{dummy|service}-{재생성 회차}` (재생성하면 회차가 +1).
- **`format` 표기는 통일해 주세요.** 포맷별 성과가 이 문자열로 집계돼요. 예: `신입 N시간`, `POV 직장인`, `N년차 vs 신입`. 같은 포맷이 `신입 3시간` / `신입 N시간`처럼 갈리면 표본이 쪼개져서 분석이 깨져요. 허용 목록(enum)을 하나 정해 주세요.
- 카드 정보 외에 **`score`와 `reference_video_ids`도 같이 내려주세요** (아래 도하 파트).

## 2. 도하에게 (점수·분석)

1. **카드마다 점수 구성요소를 저장해 주세요.**
   `score: { viral_strength, fit, feasibility, freshness }`, `reference_video_ids: []`.
   지금은 ‘근거 문장’만 있어서, 어떤 점수가 실제 성과(우리 계정 성과 배수)를 예측하는지 사후 검증을 못 해요. 쌓이면 상관분석으로 가중치를 조정할 수 있어요.
2. **포맷 점수에 ‘우리 계정 실측 성과’를 보정 계수로 반영해 주세요.**
   `v_format_performance`(포맷별 중앙값·표본 수)를 조회하면 돼요. 예: `점수 × clamp(중앙값, 0.5, 1.5)`. **표본(n)이 3 미만인 포맷은 보정하지 마세요.**
3. **패스 사유 ‘재미없음’이 많으면** 레퍼런스 이상치 임계치를 올리고, 첫 3초 훅 강도를 별도 점수로 만들어 가중해 주세요.
4. 성과 비교 기준은 ‘같은 계정 직전 20개 게시물 조회수 중앙값 대비 배수’(`v_post_scored.multiple`)예요. 시드 계정 이상치 계산도 같은 방식이면 비교가 쉬워져요.

## 3. 승원에게 (카드 생성 API)

1. **생성 요청에 제약과 이력을 넣어 주세요.**
   - 회사 정보 리스트의 촬영 가능 인원·공간·소품을 하드 제약으로.
   - 최근 14일 사용한 `asset_ids`·`format`을 넘겨서 중복 금지 (`v_card_feedback`에서 조회).
2. **재생성 API**: `POST /cards/regenerate { card_id }` → 새 카드 반환. 직전 카드를 ‘피해야 할 예시’로 같이 넘겨 주세요. 가능하면 후보 3개를 만들고 자체 평가 후 1개만 반환(best-of-n).
3. **패스 사유별 대응**
   - 촬영 불가 → 난이도 3 카드는 하루 1장 이하
   - 톤이 안 맞음 → 채택 카드 3~5개를 브랜드 톤 few-shot, 패스 카드를 반례로
   - 이미 했음 → 중복 방지 입력
4. 성과가 좋은데 선택률이 낮은 포맷은 난이도를 낮춘 버전으로 만들어 주세요 (`/insights`에 자동으로 뜸).

## 4. 데이터는 이렇게 조회하세요

| 보고 싶은 것 | 위치 |
|---|---|
| 팀의 선택/패스 사유/재생성 | `card_events`, 요약은 `v_card_feedback` |
| 게시물 성과 + 계정 평균 대비 배수 | `v_post_scored` |
| 포맷별 성과 | `v_format_performance` |
| 카드 ↔ 게시물 연결 | `posts.card_id` (게시 후 URL 붙여넣기로 연결) |

## 5. 알아두면 좋은 한계

- 카드 ↔ 게시물 연결은 사람이 URL을 붙여넣어야 해서, 연결 안 된 게시물은 포맷 분석에서 빠져요.
- 포맷별 성과는 표본이 적으면 우연일 수 있어요. 화면과 제안 모두 n<3이면 ‘참고용’으로만 표시합니다.
- 현재 제안 규칙은 규칙 기반이에요. 데이터가 쌓이면 규칙 임계값(예: 중앙값 0.95 미만이면 하향 검토)을 같이 조정해요.
